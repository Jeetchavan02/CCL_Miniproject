## 🌟 The Core Problem & Vision

Across college campuses, hundreds of valuable personal items—laptops, college ID cards, backpacks, smartwatches, lab coats, and calculators—are misplaced each semester in seminar halls, labs, canteens, and sports grounds.

The traditional recovery workflow suffers from major flaws:
1. **Physical Register Bottlenecks**: Items handed over to security are scribbled into paper logbooks with vague handwritten notes.
2. **Zero Automated Visibility**: A student looking for a lost calculator has no way of knowing it was turned in to security three floors away.
3. **Fraudulent Ownership Claims**: Without an auditable proof-verification process, anyone can claim an expensive device by giving generic descriptions.
4. **No Visual Correlation**: Human descriptions vary wildly ("dark bag" vs. "navy blue Nike backpack").

**LostFound@CRCE** bridges this gap by unifying students and campus security officers in a single automated cloud system.

## ✨ Key Features

### 👤 Student Experience
- **One-Click Lost Reporting**: Submit lost item details (title, category, last known campus location, timestamp, and unique identifiers).
- **Direct Live Camera Snapshot**: Activate the laptop/mobile webcam with zero external apps to take instant high-res photos of found items.
- **Upload File Fallback**: Seamlessly drag and drop or upload local image files (JPEG, PNG, WebP).
- **Instant Custody Confirmation**: Receive immediate confirmation cards with image previews and item IDs upon report submission.
- **AI Match Recommendations**: Review real-time match suggestions generated by AWS Rekognition with percentage confidence scores.
- **Formal Ownership Claims**: Submit verifiable proof details (passcode hints, unique scratches, wallpaper description, zipper contents) to claim items held in custody.

### 🛡️ Campus Security Officer Desk
- **Dedicated Security Desk Portal**: High-contrast, role-guarded management interface.
- **Custody Inventory Tracker**: Real-time status badges (`reported`, `claimed`, `returned`) across all items currently in custody.
- **Claims Verification Queue**: Review student ownership claims alongside submitted proof descriptions and claimant identities.
- **One-Click Release Authorization**: Single-click `Approve & Hand Over` executes an official digital handover, marking the item as claimed and issuing a verification certificate.
- **Fraud Prevention**: Single-click `Reject` for claims with mismatched proof descriptions.

## 🤖 AI Vision & Matching Engine

When an item photo is uploaded:

1. **Amazon Rekognition Vision**: The image is analyzed using `DetectLabels` with an 80% confidence threshold.
2. **Feature Extraction**: Rekognition extracts detected labels, object bounding boxes, and categorical metadata.
3. **Similarity Algorithm**: The match engine evaluates similarity between reported lost items and newly turned-in found belongings:
   - Category match weighting.
   - Text token similarity across titles and descriptions.
   - Proximity of campus locations (e.g., Canteen, Lab 4, 4th Floor Corridor).
4. **Scored Matching**: Matches are scored from 0% to 100% and displayed in the user's **AI Matches** tab.

## 🤝 Claims & Handover Desk

To eliminate fraudulent claims, LostFound@CRCE implements a 2-step verification protocol:

1. **Claim Submission (Student)**:
   - A student identifies their misplaced belonging in the catalog.
   - They submit detailed **Proof of Ownership** describing non-public details (e.g., *"The phone has a tiny crack on bottom-left, blue mountain lockscreen wallpaper, serial ending in 492"*).
2. **Verification & Custody Release (Security Officer)**:
   - The security officer reviews the claim at the Security Desk.
   - The student presents their college ID card in person at the campus security office.
   - The officer clicks **Approve & Hand Over**:
     - Item status changes from `reported` to `claimed`.
     - An official **Handover Verified** certificate badge is generated with timestamps.
     - The item is archived from active inventory.

## 🛡️ Security & Zero-Secret Architecture

- **No Hardcoded Credentials**: Database passwords, JWT secret keys, and AWS configurations are injected at runtime via environment variables and AWS SSM Parameter Store.
- **Private Subnet RDS**: The Amazon RDS MySQL instance is isolated inside private VPC subnets with no public IP, accessible only from the EC2 security group over port 3306.
- **Short-Lived S3 Presigned URLs**: Image uploads and downloads use time-limited presigned URLs (15-minute expiration), keeping the S3 bucket private.
- **Strict Role-Based Access Control**: Sensitive actions (claim approvals, custody releases) are guarded server-side and restricted to users with the `security` role.
- **Input Sanitization**: Pydantic validates and sanitizes all incoming payloads to prevent SQL injection and malformed inputs.
